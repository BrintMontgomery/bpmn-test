# SPS-001 — Interview Subject to Use a Spreadsheet

## Actors

* Interviewer  
* Subject  
* Spreadsheet Application

## Context

This procedure describes interviewing a subject and observing a simple spreadsheet task so the interviewer can document a use case for opening and using a spreadsheet.

## Preconditions

* Interviewer has a use-case template available.  
* Subject is available for the interview.  
* Subject has access to a spreadsheet application.  
* A representative spreadsheet file is available, or the Subject can describe the file used for the task.

## Outcome

The interviewer has a reviewed use case that describes why the Subject opens the spreadsheet, how the Subject opens it, the basic task performed, and how the work is saved. Any access or task difficulties are recorded for follow-up.

Version

* Spreadsheet Use Case Interview — 2026-08-13 — v1.0

## Main Path

1. **Interviewer** prepares the use-case template and confirms the interview objective.  
2. **Interviewer** explains the objective to the **Subject** and asks the Subject to describe a typical spreadsheet task.  
3. **Subject** describes the task, the information needed, and the spreadsheet file used.  
4. **Interviewer** asks the **Subject** to demonstrate how the spreadsheet is opened.  
5. **Subject** opens the **Spreadsheet Application** and selects the spreadsheet file.  
6. **Spreadsheet Application** displays the workbook to the **Subject**.  
7. **Interviewer** asks the **Subject** to demonstrate the basic spreadsheet activity, such as selecting a cell, entering information, and saving the workbook.  
8. **Subject** performs the activity and saves the workbook.  
9. **Interviewer** records the Subject's goal, actions, terms, and any decisions in the use-case template.  
10. **Interviewer** reviews the drafted use case with the **Subject** and confirms that it reflects the demonstrated task \[a\].

## Options from main path:

### Option A - Subject Cannot Open the Spreadsheet

Trigger: The Subject cannot open the spreadsheet application or locate the spreadsheet file.

1. Subject describes the problem to the Interviewer.  
2. Interviewer asks the Subject to explain what was expected to happen and what happened instead.  
3. Interviewer records the problem and the last successful action in the use case.  
4. Interviewer continues the interview using the Subject's verbal description when a demonstration cannot be completed.

### Option B - No Representative Spreadsheet Is Available

Trigger: The Subject does not have a spreadsheet file that can be used during the interview.

1. Interviewer asks the Subject to describe the usual file name, location, and purpose.  
2. Subject describes the steps normally used to open and work with the spreadsheet.  
3. Interviewer records the described steps and marks the opening and use actions as not directly observed.

### Option C - Subject Demonstrates an Additional Task

Trigger: The Subject demonstrates a task beyond opening the spreadsheet and completing the basic activity.

1. Interviewer asks the Subject whether the additional task is part of the normal use case.  
2. Subject explains the additional task and when it is performed.  
3. Interviewer records the additional task separately and keeps the basic opening and use flow in the primary use case.

## Notes

\[a\] The use case should capture the Subject's actual language and actions; it is not a replacement for a software training guide.
